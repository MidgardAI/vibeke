Vibeke 0.18.0 adds an Overview page to the desktop and browser apps. It also lets you send a queued message to Claude Code or Codex at once. The count of background work is now correct, and it includes sub-agents.

## What's new

### Overview

The desktop and browser apps open a new **Overview** page. It shows what needs you across all your hosts.

- On a computer, it counts the agents that wait for you, the agents that work, and the work that is ready to review. It lists open requests, and you can answer them there. It also lists the agents that work now and recent activity.
- On a phone, it shows a tile for each workspace above a feed of activity. Tap a tile to show only that workspace.
- Press `Cmd+Shift+H` (`Ctrl+Shift+H` on Windows and Linux) to open it on the desktop.

[Overview on the desktop](https://vibeke.dev/docs/desktop#overview)

### Send a queued message now

Claude Code and Codex keep a message in a queue when you send it while they work. The apps now show such a message above the input box with a **Queued** label. **Send now** stops the agent's current step and gives it the message at once.

- For Claude Code, Vibeke presses your `chat:sendNow` key. The default is `ctrl+x ctrl+s`. Vibeke reads your own key from `~/.claude/keybindings.json`.
- For Codex, Vibeke presses `esc` while Codex shows "Messages to be submitted after next tool call".
- Scripts can use `vibeke agent queued` and `vibeke agent send-now`, or the API methods `agent.queued` and `agent.send_now`.

[Messages that wait](https://vibeke.dev/docs/mobile#messages-that-wait)

### Background work counts are correct

The sidebar shows background work as `⧗` with a label such as `idle · 2 bg`. This count now goes down when the work ends.

- Claude Code tasks that finish while the agent works are now counted as finished.
- A Codex command that finished in the same step that started it no longer stays in the count.
- After a restart or a resumed session, work from an earlier agent process no longer comes back.

### Sub-agents count as background work

- **Codex:** sub-agents count from when they start until they finish or are closed. Messages from Codex's other threads, such as sub-agents and memory updates, no longer change the pane's agent. Before, such a message could switch the pane to the wrong session.
- **oh-my-pi:** async jobs, both `task` subagents and background `bash`, now show up.
- **pi:** background runs from the `pi-subagents` package now show up.
- **Other agents:** Vibeke counts only shell commands that the agent started with a tool call. MCP servers that start with the agent, and commands that you start yourself, no longer count.

[Background work](https://vibeke.dev/docs/concepts/agents#background-work)

## Install the terminal CLI

Available for **macOS on Apple silicon or Intel** and **Linux on x86_64 or ARM64**.
Install `minisign` first (`brew install minisign` on macOS, or your Linux package manager), then run:

```sh
curl -fsSL https://vibeke.dev/install.sh | VIBEKE_VERSION=0.18.0 sh
```

The installer verifies the release signature, checksum, and version, and installs inside your home directory.
Add `~/.local/bin` to your `PATH` if needed.

Start in your project:

```sh
cd your-project
vibeke
```

Complete first-run setup, then run `claude`, `codex`, or your usual agent command in a pane.
Press **Ctrl+B** and wait to see every key, or press **Ctrl+B**, then **:** to open the command palette.

[Installation guide](https://vibeke.dev/docs/install) · [Your first workspace](https://vibeke.dev/docs/quickstart)

## Use your phone or browser

Open [app.vibeke.dev](https://app.vibeke.dev). With a Vibeke session running on your host, open the **Devices** tab of the Connections view (`prefix+alt+d`, or **Pair a phone** in the command palette), or run:

```sh
vibeke gateway pair
```

Scan the QR code or open the link, then compare and confirm the device fingerprint.
The server manages the gateway after setup.

[Phone and browser guide](https://vibeke.dev/docs/mobile) · [Sharing and handoffs](https://vibeke.dev/docs/handoff)

## Upgrading and limitations

- Update with `vibeke update`, or with **Update Vibeke…** in the command palette. From 0.14.1 or older, run the installer once instead (see the 0.14.2 notes).
- After the update, Vibeke refreshes the integrations it manages. Restart running agent sessions so they load the new hooks and plugins. pi and oh-my-pi need a restart to report their background jobs.
- 0.18.0 can talk to 0.17.x. The API only gained methods and events, and the render protocol is unchanged. Running panes survive the update.
- **Send now** needs full access. It refuses while the agent shows a question or an approval.
- For Claude Code, **Send now** needs a key that a terminal can send. If your `chat:sendNow` key is only `ctrl+enter`, add a second key such as `ctrl+x ctrl+s`.
- For Codex, **Send now** only sends messages that wait for the next tool call. A follow-up that you queued with `tab` waits for the end of the turn.
- Desktop releases update in the app where supported; otherwise download the 0.18.0 package.
- Linux host CLI binaries use static musl linking.
- The macOS app is signed with an Apple Developer ID and notarized by Apple. The Windows installer is not publisher-signed, so Windows can ask you to approve it.
- Holder processes preserve running panes after a client disconnect or server restart. A host restart stops those processes.

[SHA256SUMS](https://github.com/vibeke-ai/vibeke/releases/download/v0.18.0/SHA256SUMS) and its [minisign signature](https://github.com/vibeke-ai/vibeke/releases/download/v0.18.0/SHA256SUMS.minisig) cover the CLI and desktop downloads, including the desktop update feed files.
See [release verification](https://vibeke.dev/docs/releases).
