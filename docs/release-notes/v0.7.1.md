Vibeke 0.7.1 makes collision warnings accurate. Agents that work outside a git checkout no longer cause warnings, and each warning says which agents did what.

## What's new

### Collision warnings

A collision warning says that two agents may have changed the same file in one checkout. In 0.7.0, these warnings often listed files that no agent had changed.

- **Git checkouts only.** Vibeke tracks agents only when they work inside a git checkout. It does not track agents in your home directory or in a folder outside a repository. Before, agents started in your home directory showed warnings about program files, such as agent settings and databases. These warnings never went away.
- **Clear wording.** A warning names the agents, what they did and the file. Examples: "claude and codex both edited `src/auth.ts`", or "codex edited `api/auth.ts` after claude read it".
- **Guesses are marked.** Sometimes no agent reports an edit, for example when a shell command or a formatter changes a file. Vibeke then guesses which agent made the edit. A warning that is based on a guess says "may" and does not send a notification. When more than three agents are working, Vibeke does not guess. An agent that formats a file it just edited no longer causes a warning.
- **Warnings go away.** Each file leaves its warning 30 minutes after the last conflicting edit. Each checkout has one warning.
- **A tidier sidebar.** Each workspace shows one line for its most important collision. The count "+N more" stands for the others. Hints about edits in the same folder are listed only in the collision view (`collisions` in the command palette).

## Install the terminal CLI

Available for **macOS on Apple silicon** and **Linux on x86_64 or ARM64**.
Install `minisign` first (`brew install minisign` on macOS, or your Linux package manager), then run:

```sh
curl -fsSL https://vibeke.dev/install.sh | VIBEKE_VERSION=0.7.1 sh
```

The installer verifies the release signature, checksum, and version, and installs inside your home directory.
Add `~/.local/bin` to your `PATH` if needed.

Start in your project:

```sh
cd your-project
vibeke
```

Complete first-run setup, then run `claude`, `codex`, or your usual agent command in a pane.
Press **Ctrl+B** and wait to see every key, or press **Ctrl+B**, then **:** to open the command palette.

## Use your phone or browser

Open [app.vibeke.dev](https://app.vibeke.dev). With a Vibeke session running on your host, open the **Devices** tab of the Connections view (`prefix+alt+d`, or **Pair a phone** in the command palette), or run:

```sh
vibeke gateway pair
```

Scan the QR code or open the link, then compare and confirm the device fingerprint.
The server manages the gateway after setup.
Suggested replies and summaries need the host assistant. Set it up and allow it on the host first.

[Phone and browser guide](https://vibeke.dev/docs/mobile) · [Sharing and handoffs](https://vibeke.dev/docs/handoff)

## Upgrading and limitations

- Run the installer again, or use **Update Vibeke…** in the command palette (`vibeke update` from a shell). Then start `vibeke`: it restarts an older server for you. The restart closes old collision warnings.
- The render protocol is the same as in 0.7.0. The phone and browser app is unchanged.
- Desktop releases update in the app where supported; otherwise download the 0.7.1 package.
- Linux host CLI binaries use static musl linking.
- The macOS desktop app is ad-hoc signed and is not notarized. The Windows installer is not publisher-signed. OS approval may be required.
- Holder processes preserve running panes after a client disconnect or server restart. A host restart stops those processes.

[SHA256SUMS](https://github.com/MidgardAI/vibeke/releases/download/v0.7.1/SHA256SUMS) and its [minisign signature](https://github.com/MidgardAI/vibeke/releases/download/v0.7.1/SHA256SUMS.minisig) cover the CLI and desktop downloads, including the desktop update feed files.
See [release verification](https://vibeke.dev/docs/releases).
