Vibeke 0.10.0 runs agents in cloud sandboxes. You can send an agent to a sandbox on Fly.io Sprites or E2B and bring it back later. Agents can also show you images. In the browser app, you can open the full terminal interface.

## What's new

### Cloud sandboxes

A cloud sandbox is a computer in the cloud that runs one task. The agent works on a copy of your code there, so it can't touch your own computer. The agent keeps working when your laptop sleeps.

- **Two providers.** Vibeke supports [Fly.io Sprites](https://sprites.dev) and [E2B](https://e2b.dev). You need an account with the provider. The provider bills you for the sandboxes.
- **Sign in once.** Sign in from the **Sandboxes** view in the terminal interface, the desktop app or the browser app, or run `vibeke cloud login sprites`. You can paste a token, use your existing `fly` or `e2b` login, or set `SPRITES_TOKEN` or `E2B_API_KEY`. Vibeke keeps the token in your system keychain.
- **Start a task in the cloud.** Run `vibeke task new "Cloud task" --isolate cloud --provider sprites`. Every pane of the task runs in the sandbox.
- **Send an agent.** Choose **Send to cloud…** on a pane: in the command palette, from the pane menu, or with the **Cloud** button in the workspace header of the apps. Vibeke waits until the agent finishes its turn. It then copies your work, including changes you have not committed, and resumes the agent in the sandbox.
- **Bring it back.** Choose **Bring back** to move the agent and its work back to this computer or to another computer you have paired.
- **See and clean up sandboxes.** The **Sandboxes** view lists every sandbox with its state. It can suspend, resume, adopt or destroy a sandbox. **Clean up…** shows the sandboxes it would remove before it removes them. Vibeke doesn't destroy a sandbox that holds work you don't have yet, unless you ask it to.
- **Panes survive restarts.** When your computer restarts, a cloud pane connects to the same shell in the sandbox again.

[Cloud sandboxes guide](https://vibeke.dev/docs/cloud-sandboxes)

### Agents can show images

An agent can attach an image, such as a screenshot from a test, with `vibeke screenshot add <file>` or the `show_image` tool. You see it in the **Screenshots** tab of the workspace panel in the apps, or with `:screenshots` in the terminal interface.

[Show an agent image](https://vibeke.dev/docs/previews)

### The terminal interface in the browser

The browser app can now run the full terminal interface. After you pair the browser, choose **Open terminal**. This also works for a workspace that someone shared with you.

## Install the terminal CLI

Available for **macOS on Apple silicon** and **Linux on x86_64 or ARM64**.
Install `minisign` first (`brew install minisign` on macOS, or your Linux package manager), then run:

```sh
curl -fsSL https://vibeke.dev/install.sh | VIBEKE_VERSION=0.10.0 sh
```

The installer verifies the release signature, checksum, and version, and installs inside your home directory.
Add `~/.local/bin` to your `PATH` if needed.

Start in your project:

```sh
cd your-project
vibeke
```

Complete first-run setup, then run `claude`, `codex`, or your usual agent command in a pane.
Press **Ctrl+B** and wait to see every key, or press **Ctrl+B**, then **:** to open the command palette.

[Installation guide](https://vibeke.dev/docs/install) · [Your first workspace](https://vibeke.dev/docs/quickstart)

## Use your phone or browser

Open [app.vibeke.dev](https://app.vibeke.dev). With a Vibeke session running on your host, open the **Devices** tab of the Connections view (`prefix+alt+d`, or **Pair a phone** in the command palette), or run:

```sh
vibeke gateway pair
```

Scan the QR code or open the link, then compare and confirm the device fingerprint.
The server manages the gateway after setup.
Suggested replies and summaries need the host assistant. Set it up and allow it on the host first.

[Phone and browser guide](https://vibeke.dev/docs/mobile) · [Sharing and handoffs](https://vibeke.dev/docs/handoff)

## Upgrading and limitations

- Run the installer again, or use **Update Vibeke…** in the command palette (`vibeke update` from a shell). Then start `vibeke`: it restarts an older server for you.
- The render protocol changed. A terminal interface from an older version can't connect to a 0.10.0 server. Update the CLI on every computer you connect from.
- A cloud sandbox gets the Linux `vibeke` of the same version as your host. Vibeke downloads it and checks its signature. Your host must be able to reach GitHub releases.
- Cloud sandboxes use the provider's network. Vibeke's network profiles for local sandboxes don't apply there.
- A session that another computer started in a sandbox keeps running after you adopt the sandbox. Hooks inside that session can't reach your computer until the agent restarts.
- Desktop releases update in the app where supported; otherwise download the 0.10.0 package.
- Linux host CLI binaries use static musl linking.
- The macOS app is signed with an Apple Developer ID and notarized by Apple. The Windows installer is not publisher-signed, so Windows can ask you to approve it.
- Holder processes preserve running panes after a client disconnect or server restart. A host restart stops those processes. Panes in a cloud sandbox reconnect to the same shell after a host restart.

[SHA256SUMS](https://github.com/MidgardAI/vibeke/releases/download/v0.10.0/SHA256SUMS) and its [minisign signature](https://github.com/MidgardAI/vibeke/releases/download/v0.10.0/SHA256SUMS.minisig) cover the CLI and desktop downloads, including the desktop update feed files.
See [release verification](https://vibeke.dev/docs/releases).
