Vibeke 0.3.0 adds updates from inside the terminal and desktop apps, Vibeke accounts for the hosted relay, and native cards for agent menus such as `/model`. It also hardens isolation, pane permissions and pairing after a security review.

## What's new

- **Update from the app.** In the terminal interface, open the command palette and choose **Check for updates** or **Update Vibeke…**. The sidebar shows when a release is available. Vibeke verifies the signed release before installing it, then reopens the same session and panes. From a shell, use `vibeke update --check`, `vibeke update`, or `vibeke update --rollback`.
- **Desktop updates.** Use **Check for Updates…** in the app menu or **Settings → About**. A button above the sidebar footer opens the release details; download and restart when you are ready. In-app installation works for the Windows EXE and the Linux AppImage. Mac builds without publisher signing and Linux DEB installs link to the download instead.
- **Vibeke accounts and the hosted relay.** `vibeke login` signs the host in with a device code: open the printed URL on any device and confirm the code. `vibeke whoami` and `vibeke logout` show and end the session. The account relay is `cloud.vibeke.dev`; `relay.vibeke.dev` still accepts hosts without an account.
- **Sign in from the Devices view.** When the relay needs a Vibeke account and you are not signed in, the Devices view first shows a sign-in code with a QR code; approve it on any device and the pairing link follows. The list shows the signed-in account, and `s` starts a sign-in.
- **Agent menus as cards.** When an agent opens a menu such as `/model`, `/effort` or `/resume`, Vibeke shows it as a card in the TUI, desktop and phone apps and answers it in the agent's own terminal. Unrecognised dialogs are held for you instead of being answered.
- **Slash-command autocomplete and model switcher.** The composer suggests the agent's slash commands, and a model switcher changes the model of a running agent. The run's model follows `/model` switches made inside the agent.

### Security

- Sandboxed panes can no longer reach the files that configure their own sandbox launch.
- Pane permissions are tighter. On Linux, processes that detach from a pane keep that pane's permissions. Panes can no longer read arbitrary host files through uploads or place task worktrees outside the worktree root. They need your confirmation to preview a local port they do not own. The [security model](https://vibeke.dev/docs/security) now states plainly that pane permissions guard against mistakes and prompt injection, and that only isolated execution contains an agent.
- Notification and window titles from panes are stripped of control characters before they reach your terminal.
- Pairing is rate-limited per pairing link, so one link cannot block others. Device names are sanitised in the pairing prompt. Push notifications are registered only with your own hosts, not with hosts shared with you.
- The browser app and website send a Content Security Policy and related headers.

### Compatibility

- The TUI and desktop render protocol changed. Update the CLI and the desktop app together.
- Both hosted relays run the updated relay engine: `relay.vibeke.dev` stays open without an account, and `cloud.vibeke.dev` requires one. Gateways send a relay token in an `Authorization` header and fall back once for self-hosted relays that predate it.
- Plugins brought in with `vibeke plugin import` must be approved again.
- Vibeke warns when your config file is writable by other users.
- `vibeke update` run from inside a pane is refused; run it from a terminal outside Vibeke or use the update action in the TUI.

## Install the terminal CLI

Available for **macOS on Apple silicon** and **Linux on x86_64 or ARM64**.
Install `minisign` first (`brew install minisign` on macOS, or your Linux package manager), then run:

```sh
curl -fsSL https://vibeke.dev/install.sh | VIBEKE_VERSION=0.3.0 sh
```

The installer verifies the release signature, checksum, and version, and installs inside your home directory.
Add `~/.local/bin` to your `PATH` if needed.

Start in your project:

```sh
cd your-project
vibeke
```

Complete first-run setup, then run `claude`, `codex`, or your usual agent command in a pane.
Press **Ctrl+B**, then **:** to open the command palette.

[Installation guide](https://vibeke.dev/docs/install) · [Your first workspace](https://vibeke.dev/docs/quickstart)

## Use your phone or browser

Open [app.vibeke.dev](https://app.vibeke.dev). With a Vibeke session running on your host, open the **Devices** view (`prefix+alt+d`, or **Pair a phone** in the command palette), or run:

```sh
vibeke gateway pair
```

Scan the QR code or open the link, then compare and confirm the device fingerprint.
The server manages the gateway after setup.

[Phone and browser guide](https://vibeke.dev/docs/mobile)

## Upgrading and limitations

- From 0.2.0, run the installer again to upgrade the CLI, then start `vibeke` again. Later releases can be installed from inside Vibeke.
- Install the 0.3.0 desktop package once by hand; later desktop releases can update in-app where supported.
- Linux host CLI binaries use static musl linking.
- The macOS desktop app is ad-hoc signed and is not notarized. The Windows installer is not publisher-signed. OS approval may be required.
- Holder processes preserve running panes after a client disconnect or server restart. A host restart stops those processes.

[SHA256SUMS](https://github.com/MidgardAI/vibeke/releases/download/v0.3.0/SHA256SUMS) and its [minisign signature](https://github.com/MidgardAI/vibeke/releases/download/v0.3.0/SHA256SUMS.minisig) cover the CLI and desktop downloads, including the desktop update feed files.
See [release verification](https://vibeke.dev/docs/releases).
