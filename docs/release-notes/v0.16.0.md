Vibeke 0.16.0 lets you send work to other people with one link. A designer can review a running app, a teammate can continue an agent's session, and a bot can share both. Links can be limited to GitHub accounts and teams.

## What's new

### Design review links

Share one preview with a designer: run `vibeke share review v4`, or choose **Design review** in the **People** form (`prefix+alt+v`). The designer opens the link in a web browser and uses the running app. They pick elements or areas, write notes and send them. The notes go to the agent that owns the preview. When the agent changes the app, the designer sees the new version at the same link.

You decide where the notes go. With **Straight to the agent**, the agent gets them at once. With **Hold for me**, they wait until you send or discard them in the TUI, the desktop app or the phone app. A review link reaches only that one preview. It does not give access to terminals, files or other previews.

[Design review](https://vibeke.dev/docs/sharing#share-a-running-app-for-design-review)

### Continue a session from a link

Run `vibeke handoff link --pane %3` to turn an agent session into a link: the branch, the uncommitted changes and the conversation. Add `--pr` to post the link as a comment on the pull request. A teammate opens the link, chooses one of their hosts, and continues the session there. Your computer can be off by then.

The session is encrypted before it leaves your host. The account server stores it for 7 days by default and cannot read it. The key is only in the link.

[Continue links](https://vibeke.dev/docs/handoff)

### Share with GitHub accounts and teams

Links can be limited to GitHub accounts. The person who opens the link signs in with GitHub once. One link works for several people, and each person becomes a separate device that you can remove.

Manage who can open your links on your new account page at [cloud.vibeke.dev/account](https://cloud.vibeke.dev/account):

- **People:** add GitHub usernames.
- **Teams:** create a team and invite people by GitHub username or with an invite link. Everyone in a team can open the links that a teammate shares with the team. Vibeke checks the team when someone opens a link, so new members get in and people who leave lose access.

Without other options, a GitHub link is for the people and teams on that page. Use `--github alice,bob`, `--team acme`, `--any-github` or `--link` to choose for one link.

[Sharing guide](https://vibeke.dev/docs/sharing)

### Share from scripts and chat bots

New commands make links without a person at the terminal: `vibeke share watch`, `vibeke share review`, `vibeke share list`, `vibeke share revoke`, `vibeke handoff link` and `vibeke handoff open`. A Hermes bot on Slack can now start an agent, post a link to watch it, post a design review link, and post a continue link when the work is done. `vibeke integration install hermes` adds a second skill, `vibeke-remote`, for this.

[Hermes Agent guide](https://vibeke.dev/docs/agents/hermes)

## Install the terminal CLI

Available for **macOS on Apple silicon or Intel** and **Linux on x86_64 or ARM64**.
Install `minisign` first (`brew install minisign` on macOS, or your Linux package manager), then run:

```sh
curl -fsSL https://vibeke.dev/install.sh | VIBEKE_VERSION=0.16.0 sh
```

The installer verifies the release signature, checksum, and version, and installs inside your home directory.
Add `~/.local/bin` to your `PATH` if needed.

Start in your project:

```sh
cd your-project
vibeke
```

Complete first-run setup, then run `claude`, `codex`, or your usual agent command in a pane.
Press **Ctrl+B** and wait to see every key, or press **Ctrl+B**, then **:** to open the command palette.

[Installation guide](https://vibeke.dev/docs/install) · [Your first workspace](https://vibeke.dev/docs/quickstart)

## Use your phone or browser

Open [app.vibeke.dev](https://app.vibeke.dev). With a Vibeke session running on your host, open the **Devices** tab of the Connections view (`prefix+alt+d`, or **Pair a phone** in the command palette), or run:

```sh
vibeke gateway pair
```

Scan the QR code or open the link, then compare and confirm the device fingerprint.
The server manages the gateway after setup.
Suggested replies and summaries need the host assistant. Set it up and allow it on the host first.

[Phone and browser guide](https://vibeke.dev/docs/mobile) · [Sharing and handoffs](https://vibeke.dev/docs/handoff)

## Upgrading and limitations

- Update with `vibeke update`, or with **Update Vibeke…** in the command palette. From 0.14.1 or older, run the installer once instead (see the 0.14.2 notes).
- After the update, Vibeke refreshes the integrations it manages. Restart running agent sessions so they load the new hooks and plugins.
- 0.16.0 can talk to 0.15.x. The API only gained methods, and the render protocol is unchanged. Update the host before you share links. If the host is older, the 0.16.0 command line and TUI cancel a link they asked to limit to GitHub accounts or teams, instead of handing out a link that anyone can open.
- GitHub links, teams and continue links need an account server, and the host must be signed in (`vibeke login`). With an open or self-hosted relay without an account server, only links that anyone with the link can open are available.
- An app older than 0.16.0 cannot open a GitHub link. It shows "This link needs a newer Vibeke app". The browser app at app.vibeke.dev is always current.
- A design review shows the page from your host's browser. A preview served over `https://` works the same way.
- A continue link carries at most 200 MiB and works for 7 days by default (at most 30). Files that look like secrets and untracked files over 5 MiB are left out.
- A person removed from a team can keep a session that is already open for up to about 15 minutes.
- A cloud sandbox gets the Linux `vibeke` of the same version as your host. Vibeke downloads it and checks its signature. Your host must be able to reach GitHub releases.
- Desktop releases update in the app where supported; otherwise download the 0.16.0 package.
- Linux host CLI binaries use static musl linking.
- The macOS app is signed with an Apple Developer ID and notarized by Apple. The Windows installer is not publisher-signed, so Windows can ask you to approve it.
- Holder processes preserve running panes after a client disconnect or server restart. A host restart stops those processes.

[SHA256SUMS](https://github.com/vibeke-ai/vibeke/releases/download/v0.16.0/SHA256SUMS) and its [minisign signature](https://github.com/vibeke-ai/vibeke/releases/download/v0.16.0/SHA256SUMS.minisig) cover the CLI and desktop downloads, including the desktop update feed files.
See [release verification](https://vibeke.dev/docs/releases).
