Vibeke 0.20.0 lets you answer queued Codex follow-up questions from the inbox while Codex keeps working.

## New in this release

### Answer Codex follow-up questions

Codex can ask a question while it continues working. These questions now appear in the Vibeke inbox. Choose an option or write your own answer.

Vibeke checks the question in the Codex pane before submitting your answer. It opens the question editor in the pane only when you send an answer. The inbox distinguishes a recorded answer from one Codex has received. If the question has changed or its editor cannot be read safely, Vibeke directs you to the pane.

This supports the queued follow-up questions shown by recent Codex versions, including several questions in one request. Existing blocking Codex questions continue to work.

### Prompt-cache countdowns and alerts removed

The phone, browser, and desktop interfaces no longer show prompt-cache countdowns or send cache-expiry alerts. Update the app to remove the countdowns. When the updated app syncs push notifications with an older host, it turns off cache alerts on that host.

## Install the terminal CLI

Available for **macOS 13 or later on Apple silicon or Intel** and **Linux on x86_64 or ARM64**.
Install `minisign` first (`brew install minisign` on macOS, or your Linux package manager), then run:

```sh
curl -fsSL https://vibeke.dev/install.sh | VIBEKE_VERSION=0.20.0 sh
```

The installer verifies the release signature, checksum, and version, and installs inside your home directory.
Add `~/.local/bin` to your `PATH` if needed.

Start in your project:

```sh
cd your-project
vibeke
```

Complete first-run setup, then run `claude`, `codex`, or your usual agent command in a pane.
Press **Ctrl+B** and wait to see every key, or press **Ctrl+B**, then **:** to open the command palette.

## Use your phone or browser

Open [app.vibeke.dev](https://app.vibeke.dev). With a Vibeke session running on your host, open the **Devices** tab of the Connections view (`prefix+alt+d`, or **Pair a phone** in the command palette), or run:

```sh
vibeke gateway pair
```

Scan the QR code or open the link, then compare and confirm the device fingerprint.
The server manages the gateway after setup.

[Phone and browser guide](https://vibeke.dev/docs/mobile) · [Sharing and handoffs](https://vibeke.dev/docs/handoff)

## Upgrading and limitations

- Update with `vibeke update`, or with **Update Vibeke…** in the command palette. From 0.14.1 or older, run the installer once instead (see the 0.14.2 notes).
- Update the host to answer Codex follow-up questions from the inbox. Codex must run interactively in a pane.
- Long answers, answers over eight lines, and some special text must be entered in the Codex pane.
- 0.20.0 keeps the render protocol and JSON API compatible with 0.19.0.
- Running pane processes survive a server restart. Restart the TUI client to load the new version.
- Browser shortcuts can take priority over terminal shortcuts.
- Desktop releases update in the app where supported; otherwise download the 0.20.0 package.
- Linux host CLI binaries use static musl linking.
- The macOS app is signed with an Apple Developer ID and notarized by Apple. The Windows installer is not publisher-signed, so Windows can ask you to approve it.
- Holder processes preserve running panes after a client disconnect or server restart. A host restart stops those processes.

[SHA256SUMS](https://github.com/vibeke-ai/vibeke/releases/download/v0.20.0/SHA256SUMS) and its [minisign signature](https://github.com/vibeke-ai/vibeke/releases/download/v0.20.0/SHA256SUMS.minisig) cover the CLI and desktop downloads, including the desktop update feed files.
See [release verification](https://vibeke.dev/docs/releases).
