Vibeke 0.14.0 runs more Herdr plugins without changes and adds new guides to the documentation.

## What's new

### Herdr plugins

Vibeke can run plugins written for Herdr 0.9.3. This release makes Vibeke behave much more like Herdr for these plugins.

- The `herdr` command inside a plugin prints the same output as Herdr. It accepts the same flags and has the same exit codes. It also has new commands, such as `herdr status`, `herdr pane layout` and `herdr worktree remove`.
- Plugins get the same context and events as in Herdr. This includes the focused pane, worktree details and plugin pane events.
- Many more Herdr API calls work, such as pane links, pane process information, scrolling, worktree calls and agent focus.
- Popups have the same size as in Herdr. Plugin panes in a tab show the title from the plugin manifest.

Vibeke is now tested with real Herdr plugins. A nightly job runs 15 popular plugins without changes, both in Vibeke and in Herdr 0.9.3. It then compares the results. On Linux and macOS, 13 plugins pass every step. The other 2 pass every step that the test can run.

One difference stays on purpose. A background process that a plugin action starts cannot call Vibeke after the action ends. Start such a process from a `[[startup]]` entry in the plugin manifest instead.

[Moving from Herdr](https://vibeke.dev/docs/migrating-from-herdr)

### Control API

- `workspace.create` and `tab.create` accept `env`, a map of environment variables for the new pane.
- `pane.screenshot` has a new `grid` format. It returns the visible screen as JSON cells.
- New events: `pane.metadata_reported` and `workspace.metadata_reported`.

[Control API](https://vibeke.dev/docs/api)

### Documentation

The documentation has new pages:

- Getting started: [Your first task](https://vibeke.dev/docs/first-task) and answering agents from your phone.
- Guides for running agents in parallel, remote machines, teamwork and scripting.
- A page for each agent: Claude Code, Codex CLI, pi and other agents.
- [Troubleshooting](https://vibeke.dev/docs/troubleshooting) and a [FAQ](https://vibeke.dev/docs/faq).

### Fixes

- An agent that reports its state through hooks stays active when its shell returns to the foreground. Before, Vibeke could end the run too early.

## Install the terminal CLI

Available for **macOS on Apple silicon** and **Linux on x86_64 or ARM64**.
Install `minisign` first (`brew install minisign` on macOS, or your Linux package manager), then run:

```sh
curl -fsSL https://vibeke.dev/install.sh | VIBEKE_VERSION=0.14.0 sh
```

The installer verifies the release signature, checksum, and version, and installs inside your home directory.
Add `~/.local/bin` to your `PATH` if needed.

Start in your project:

```sh
cd your-project
vibeke
```

Complete first-run setup, then run `claude`, `codex`, or your usual agent command in a pane.
Press **Ctrl+B** and wait to see every key, or press **Ctrl+B**, then **:** to open the command palette.

[Installation guide](https://vibeke.dev/docs/install) · [Your first workspace](https://vibeke.dev/docs/quickstart)

## Use your phone or browser

Open [app.vibeke.dev](https://app.vibeke.dev). With a Vibeke session running on your host, open the **Devices** tab of the Connections view (`prefix+alt+d`, or **Pair a phone** in the command palette), or run:

```sh
vibeke gateway pair
```

Scan the QR code or open the link, then compare and confirm the device fingerprint.
The server manages the gateway after setup.
Suggested replies and summaries need the host assistant. Set it up and allow it on the host first.

[Phone and browser guide](https://vibeke.dev/docs/mobile) · [Sharing and handoffs](https://vibeke.dev/docs/handoff)

## Upgrading and limitations

- Run the installer again, or use **Update Vibeke…** in the command palette (`vibeke update` from a shell). Then start `vibeke`: it restarts an older server for you.
- The render protocol did not change. A 0.13.1 terminal interface can still connect to a 0.14.0 server. The desktop app, the browser app and the API stay compatible.
- A cloud sandbox gets the Linux `vibeke` of the same version as your host. Vibeke downloads it and checks its signature. Your host must be able to reach GitHub releases.
- Cloud sandboxes use the provider's network. Vibeke's network profiles for local sandboxes do not apply there.
- Desktop releases update in the app where supported; otherwise download the 0.14.0 package.
- Linux host CLI binaries use static musl linking.
- The macOS app is signed with an Apple Developer ID and notarized by Apple. The Windows installer is not publisher-signed, so Windows can ask you to approve it.
- Holder processes preserve running panes after a client disconnect or server restart. A host restart stops those processes.

[SHA256SUMS](https://github.com/MidgardAI/vibeke/releases/download/v0.14.0/SHA256SUMS) and its [minisign signature](https://github.com/MidgardAI/vibeke/releases/download/v0.14.0/SHA256SUMS.minisig) cover the CLI and desktop downloads, including the desktop update feed files.
See [release verification](https://vibeke.dev/docs/releases).
