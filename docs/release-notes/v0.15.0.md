Vibeke 0.15.0 lets agents in different panes work together with @mentions, and lets you annotate web pages for your agents.

## What's new

### Mentions: agents that message each other

Give a pane a short name, such as `@reviewer`. Then you, or an agent in another pane, can send it a message. The answer comes back to the pane that asked.

- Press **prefix**, then **@** to open the mention picker at the cursor. It lists the other panes of the workspace by their sidebar label. Choose a pane to insert its name. A pane without a name gets one from its label. Press **Ctrl+E** to change it first.
- Start a prompt with `@reviewer` to hand the whole prompt to that agent. The answer shows up in your pane.
- Write `Ask @reviewer to check the retry logic` in a prompt, and your agent sends the request itself. It gets the answer in a later turn.
- Agents use the new MCP tools, or `vibeke msg @name "text"` and `vibeke msg reply <id> "text"`. Run `vibeke name @reviewer` to name a pane from its shell.
- The web and phone composer completes `@` names.

Vibeke delivers a message only when the agent is idle and its input box is empty. Messages stay inside one workspace, and only named panes receive them. A message is untrusted input for the agent that receives it, and it grants no permissions. Mentions work with Claude Code and Codex.

[Mentions guide](https://vibeke.dev/docs/mentions)

### Annotate web pages for your agent

- In a browser pane, press **prefix**, then **Alt+N** to switch on annotate mode. Click an element or drag over a region, then write a note. The notes panel collects your notes.
- The desktop app, the embedded preview and the phone preview have **Annotate** and **Notes** too.
- An agent can ask for your notes with `vibeke browser feedback` or the `browser_feedback` MCP tool.

[Previews guide](https://vibeke.dev/docs/previews)

### Agents and integrations

- **Codex hooks work again in more setups.** Codex attached each pane to its shared background server. That server ran the hooks without the pane's identity, so Vibeke saw Codex only through the screen. The Vibeke `codex` wrapper now starts Codex with `--no-daemon` when your Codex supports it. Vibeke rewrites the wrapper after the update.
- A new Hermes Agent integration. The OpenCode plugin was checked against OpenCode 1.19.
- Each integration installs the Vibeke skill. Vibeke refreshes its managed files after an update, and asks before it changes outdated hooks.
- `vibeke ssh` offers to install integrations on the remote host.
- `vibeke doctor` warns when a named agent has no hooks or MCP server.

### Other changes

- The host CLI now runs on Intel Macs (`vibeke-macos-x86_64`).
- The sidebar and the composer no longer show a yolo badge.

## Install the terminal CLI

Available for **macOS on Apple silicon or Intel** and **Linux on x86_64 or ARM64**.
Install `minisign` first (`brew install minisign` on macOS, or your Linux package manager), then run:

```sh
curl -fsSL https://vibeke.dev/install.sh | VIBEKE_VERSION=0.15.0 sh
```

The installer verifies the release signature, checksum, and version, and installs inside your home directory.
Add `~/.local/bin` to your `PATH` if needed.

Start in your project:

```sh
cd your-project
vibeke
```

Complete first-run setup, then run `claude`, `codex`, or your usual agent command in a pane.
Press **Ctrl+B** and wait to see every key, or press **Ctrl+B**, then **:** to open the command palette.

[Installation guide](https://vibeke.dev/docs/install) · [Your first workspace](https://vibeke.dev/docs/quickstart)

## Use your phone or browser

Open [app.vibeke.dev](https://app.vibeke.dev). With a Vibeke session running on your host, open the **Devices** tab of the Connections view (`prefix+alt+d`, or **Pair a phone** in the command palette), or run:

```sh
vibeke gateway pair
```

Scan the QR code or open the link, then compare and confirm the device fingerprint.
The server manages the gateway after setup.
Suggested replies and summaries need the host assistant. Set it up and allow it on the host first.

[Phone and browser guide](https://vibeke.dev/docs/mobile) · [Sharing and handoffs](https://vibeke.dev/docs/handoff)

## Upgrading and limitations

- Update with `vibeke update`, or with **Update Vibeke…** in the command palette. From 0.14.1 or older, run the installer once instead (see the 0.14.2 notes).
- The render protocol changed. A 0.14 terminal interface cannot attach to a 0.15 server, and the other way around. Update the host and every machine you attach from. Remote machines update with `vibeke machine upgrade <machine>`. The desktop app, the browser app and the API stay compatible.
- Restart Codex sessions after the update so they start with `--no-daemon`. A Codex session started this way does not appear in `codex agents`, and it stops when you close its pane.
- A cloud sandbox gets the Linux `vibeke` of the same version as your host. Vibeke downloads it and checks its signature. Your host must be able to reach GitHub releases.
- Desktop releases update in the app where supported; otherwise download the 0.15.0 package.
- Linux host CLI binaries use static musl linking.
- The macOS app is signed with an Apple Developer ID and notarized by Apple. The Windows installer is not publisher-signed, so Windows can ask you to approve it.
- Holder processes preserve running panes after a client disconnect or server restart. A host restart stops those processes.

[SHA256SUMS](https://github.com/vibeke-ai/vibeke/releases/download/v0.15.0/SHA256SUMS) and its [minisign signature](https://github.com/vibeke-ai/vibeke/releases/download/v0.15.0/SHA256SUMS.minisig) cover the CLI and desktop downloads, including the desktop update feed files.
See [release verification](https://vibeke.dev/docs/releases).
