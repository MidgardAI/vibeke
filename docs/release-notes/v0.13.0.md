Vibeke 0.13.0 makes collision warnings easier to act on and fixes problems with images and browser panes in the terminal interface.

## What's new

### Collision warnings in the sidebar

A collision happens when two agents edit the same files. The sidebar shows one line for the most serious collision.

- Click the collision line to open the collision view. The view shows the whole headline, the paths, the runs, and a timeline.
- Press `d` in the collision view to dismiss the warning. The sidebar line and the `⚠` marks go away. Vibeke keeps tracking the collision. The warning comes back when another agent joins the collision, or when the collision becomes more serious. Press `d` again to show a dismissed warning.
- From a shell, run `vibeke collision dismiss <collision>`.

[Agents sharing one checkout](https://vibeke.dev/docs/tasks#agents-sharing-one-checkout)

### Whole text of long sidebar rows

A sidebar row that is too long ends in `…`. Rest the mouse pointer on the row to see its whole text. In navigate mode, select the row to see its whole text.

### Fixes

- The image card no longer says "The image file is gone (retention)" for a new image. Before, the terminal interface could ask for an image before the server had stored it. The terminal interface now also looks for a missing image again a few times before it gives up.
- Images show in Ghostty when the terminal interface runs with its own `TMPDIR`. Ghostty only reads image files from its own temporary folder. Vibeke now writes these files to the temporary folder of the system.
- A browser pane that two terminals show at different sizes now fills the pane in both. Before, the second terminal showed the page small in a corner. Clicks in the second terminal go to the right place on the page.

## Install the terminal CLI

Available for **macOS on Apple silicon** and **Linux on x86_64 or ARM64**.
Install `minisign` first (`brew install minisign` on macOS, or your Linux package manager), then run:

```sh
curl -fsSL https://vibeke.dev/install.sh | VIBEKE_VERSION=0.13.0 sh
```

The installer verifies the release signature, checksum, and version, and installs inside your home directory.
Add `~/.local/bin` to your `PATH` if needed.

Start in your project:

```sh
cd your-project
vibeke
```

Complete first-run setup, then run `claude`, `codex`, or your usual agent command in a pane.
Press **Ctrl+B** and wait to see every key, or press **Ctrl+B**, then **:** to open the command palette.

[Installation guide](https://vibeke.dev/docs/install) · [Your first workspace](https://vibeke.dev/docs/quickstart)

## Use your phone or browser

Open [app.vibeke.dev](https://app.vibeke.dev). With a Vibeke session running on your host, open the **Devices** tab of the Connections view (`prefix+alt+d`, or **Pair a phone** in the command palette), or run:

```sh
vibeke gateway pair
```

Scan the QR code or open the link, then compare and confirm the device fingerprint.
The server manages the gateway after setup.
Suggested replies and summaries need the host assistant. Set it up and allow it on the host first.

[Phone and browser guide](https://vibeke.dev/docs/mobile) · [Sharing and handoffs](https://vibeke.dev/docs/handoff)

## Upgrading and limitations

- Run the installer again, or use **Update Vibeke…** in the command palette (`vibeke update` from a shell). Then start `vibeke`: it restarts an older server for you.
- The render protocol did not change. A 0.12.0 terminal interface can still connect to a 0.13.0 server.
- A cloud sandbox gets the Linux `vibeke` of the same version as your host. Vibeke downloads it and checks its signature. Your host must be able to reach GitHub releases.
- Cloud sandboxes use the provider's network. Vibeke's network profiles for local sandboxes do not apply there.
- Desktop releases update in the app where supported; otherwise download the 0.13.0 package.
- Linux host CLI binaries use static musl linking.
- The macOS app is signed with an Apple Developer ID and notarized by Apple. The Windows installer is not publisher-signed, so Windows can ask you to approve it.
- Holder processes preserve running panes after a client disconnect or server restart. A host restart stops those processes.

[SHA256SUMS](https://github.com/vibeke-ai/vibeke/releases/download/v0.13.0/SHA256SUMS) and its [minisign signature](https://github.com/vibeke-ai/vibeke/releases/download/v0.13.0/SHA256SUMS.minisig) cover the CLI and desktop downloads, including the desktop update feed files.
See [release verification](https://vibeke.dev/docs/releases).
