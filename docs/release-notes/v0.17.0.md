Vibeke 0.17.0 makes the terminal interface faster under load. It also runs design reviews in the reviewer's own browser. Notes from a review now reach a busy agent without typing over you.

## What's new

### A faster terminal interface

Typing and drawing stay quick when panes print a lot of output. Vibeke now saves scrollback outside the loop that runs each pane. The terminal interface draws less on each frame. It also reuses rows that did not change. Slow history reads and waiting frames no longer hold up other panes.

Scrollback that waits to be saved survives a normal stop and restart. If a save fails, Vibeke tries again later and keeps the waiting history. If the server must stop by force, it records this, and the next start recovers.

`vibeke server status --json` now reports render counters under `render`.

### Design reviews run in the reviewer's browser

A design review link now opens the running app in the designer's own browser. Every request goes end-to-end encrypted through your host to your dev server. Hot reload works, and the designer can use their browser's developer tools. Each review link gets its own web address, so its cookies stay separate.

A preview served over `https://`, or a browser that blocks service workers, still gets a picture stream from your host's browser.

[Design review](https://vibeke.dev/docs/sharing#share-a-running-app-for-design-review)

### Notes reach busy agents safely

Notes from a review or from the preview panel now wait for a good moment:

- A working agent gets the notes with its next step, or when it finishes its turn. Claude Code and Codex receive them through Vibeke's hooks. Vibeke does not type into the input box then.
- An idle agent gets the notes typed into its input box. Vibeke does this only when nobody typed in that pane in the last few seconds, and when the input box is empty.
- Otherwise the notes wait. The notes panel says why, for example "waiting: someone is typing in that pane".

The owner of the preview can deliver waiting notes at once. Press `S` in the notes panel, or choose **Send now** in the app.

[When notes wait](https://vibeke.dev/docs/previews#when-notes-wait)

### The same keys in every form

Every form, dialog and tabbed view in the terminal interface now uses the same keys:

- `left`, `right` or `space` change the selected option.
- `up`, `down`, `tab` and `shift+tab` move between the fields.
- `enter` confirms, and `esc` goes back.

To switch tabs from a form, press `up` from the top row, then use `left` and `right`. The letter shortcuts that a view shows still work.

[Keys in forms and tabbed views](https://vibeke.dev/docs/terminal#keys-in-forms-and-tabbed-views)

### Other changes

- A shared pane or workspace now opens in the app's own view first. The terminal view is an option.
- Vibeke uses the account server that the relay names. Without one, it uses cloud.vibeke.dev. It never uses the address of an open relay as an account server.

## Install the terminal CLI

Available for **macOS on Apple silicon or Intel** and **Linux on x86_64 or ARM64**.
Install `minisign` first (`brew install minisign` on macOS, or your Linux package manager), then run:

```sh
curl -fsSL https://vibeke.dev/install.sh | VIBEKE_VERSION=0.17.0 sh
```

The installer verifies the release signature, checksum, and version, and installs inside your home directory.
Add `~/.local/bin` to your `PATH` if needed.

Start in your project:

```sh
cd your-project
vibeke
```

Complete first-run setup, then run `claude`, `codex`, or your usual agent command in a pane.
Press **Ctrl+B** and wait to see every key, or press **Ctrl+B**, then **:** to open the command palette.

[Installation guide](https://vibeke.dev/docs/install) · [Your first workspace](https://vibeke.dev/docs/quickstart)

## Use your phone or browser

Open [app.vibeke.dev](https://app.vibeke.dev). With a Vibeke session running on your host, open the **Devices** tab of the Connections view (`prefix+alt+d`, or **Pair a phone** in the command palette), or run:

```sh
vibeke gateway pair
```

Scan the QR code or open the link, then compare and confirm the device fingerprint.
The server manages the gateway after setup.
Suggested replies and summaries need the host assistant. Set it up and allow it on the host first.

[Phone and browser guide](https://vibeke.dev/docs/mobile) · [Sharing and handoffs](https://vibeke.dev/docs/handoff)

## Upgrading and limitations

- Update with `vibeke update`, or with **Update Vibeke…** in the command palette. From 0.14.1 or older, run the installer once instead (see the 0.14.2 notes).
- After the update, Vibeke refreshes the integrations it manages. Restart running agent sessions so they load the new hooks and plugins. Busy agents get notes through these hooks.
- 0.17.0 can talk to 0.16.x. The API only gained fields, and the render protocol is unchanged. Running panes survive the update.
- In a design review that runs in the designer's browser, an app that calls another port on your computer, such as an API on a different port, cannot reach it.
- Send now skips the idle, typing and empty input checks. It still refuses when the agent run has ended or when a question is open. Reviewers cannot use it.
- Desktop releases update in the app where supported; otherwise download the 0.17.0 package.
- Linux host CLI binaries use static musl linking.
- The macOS app is signed with an Apple Developer ID and notarized by Apple. The Windows installer is not publisher-signed, so Windows can ask you to approve it.
- Holder processes preserve running panes after a client disconnect or server restart. A host restart stops those processes.

[SHA256SUMS](https://github.com/vibeke-ai/vibeke/releases/download/v0.17.0/SHA256SUMS) and its [minisign signature](https://github.com/vibeke-ai/vibeke/releases/download/v0.17.0/SHA256SUMS.minisig) cover the CLI and desktop downloads, including the desktop update feed files.
See [release verification](https://vibeke.dev/docs/releases).
